# 거래처 통합 식별·매핑 명세

- 작업 기준: `origin/main` `f43af597b9eb86e35bd40b3ff5b466c1c75f3349`
- 확인 문서: `AGENTS.md` 2.3.3, `APP_ARCHITECTURE.md` 2.1.5, `app-manifest.json`의 `customer-master` 계약
- 현재 상태: NEXUS 거래처 원본과 ERP·SHOP 외부코드는 독립 DB에 저장되지만, 서로 다른 원본 행이 별도 NEXUS 거래처로 생성된 경우 이를 되돌릴 수 있는 관리 화면이 없다.
- 목표 상태: NEXUS·ERP·SHOP 코드 중 하나로 같은 대표 거래처를 조회하고, 관리자가 분산 거래처를 가역적으로 연결·해제한다.
- 변경 경계: `oneapp-customermaster-v1`의 기존 Store와 Snapshot Schema를 유지한다. 다른 앱, Cloud, 인증·권한 및 운영 v17 원본은 변경하지 않는다.

## 1. 식별 구조

거래처의 영구 식별값은 `customerId`인 NEXUS 거래처코드다. ERP 거래처코드와 SHOP 회원 아이디는 `customerSourceLinks`의 개별 외부코드 연결로 저장한다.

```text
NEXUS CU-대표
├─ ERP 6151068868
├─ SHOP aksvh
└─ SHOP wjddbs
```

한 거래처에는 ERP 코드와 SHOP 회원 아이디를 각각 여러 개 연결할 수 있다. 외부코드는 문자열로 합치지 않고 `sourceSystem + sourceCustomerCode` 단위로 보존한다.

## 2. 기본 자동 매핑 순서

1. 같은 NEXUS 거래처코드가 있으면 해당 거래처를 사용한다.
2. 같은 `원본 시스템 + 외부코드` 연결이 있으면 기존 NEXUS 거래처를 사용한다.
3. ERP 업로드는 ERP 거래처코드 완전 일치만 자동 연결한다.
4. SHOP 업로드는 다음의 유일한 강한 일치만 자동 연결한다.
   - 사업자번호 완전 일치
   - 정규화 거래처명 + 휴대폰 완전 일치
   - 정규화 거래처명 + 이메일 완전 일치
5. 거래처명만 같거나 후보가 여러 건이면 자동 확정하지 않고 관리자 확인 대상으로 둔다.
6. 파일 헤더가 명확하면 ERP·SHOP 원본 종류를 자동 판별한다. 판별 결과와 다른 원본 종류로는 분석을 실행하지 않는다.

빈 Excel 값은 기존값을 유지하고 숫자 `0`은 정상값으로 반영한다. 외부코드 일치는 원본 시스템을 포함해 판정한다.

## 3. 관리자 수동 연결

- 관리자는 분리된 NEXUS 거래처와 대표 NEXUS 거래처를 각각 선택한다.
- 분리 거래처는 `qualityStatus=SUPERSEDED`, `canonicalCustomerId=대표 customerId`로 연결한다.
- 분리 거래처와 외부코드는 삭제하거나 물리적으로 이동하지 않는다.
- NEXUS·ERP·SHOP 코드 중 어느 값으로 검색해도 대표 NEXUS 거래처를 반환한다.
- Read Adapter는 분리 거래처의 별칭과 외부코드를 대표 NEXUS 거래처코드로 투영한다.
- 연결과 해제는 각각 새 Revision과 작업이력으로 기록한다.

## 4. 연결 해제

- 관리자가 연결 해제를 선택하면 분리 거래처의 기존 `customerId`와 외부코드는 그대로 복원한다.
- 연결 전 품질 상태를 복원하고 `canonicalCustomerId`는 자기 자신으로 되돌린다.
- 대표 거래처 데이터와 과거 작업이력을 삭제하거나 자동 덮어쓰지 않는다.

## 5. 완료 조건

- NEXUS 코드, ERP 코드, SHOP 회원 아이디 검색이 같은 대표 거래처를 반환한다.
- 연결 후 거래처 목록과 Snapshot에는 대표 거래처 한 건만 운영 거래처로 표시된다.
- 한 NEXUS 거래처 상세 화면에서 연결된 ERP·SHOP 코드를 모두 확인할 수 있다.
- 연결 해제 후 원래 거래처가 다시 표시된다.
- 연결·해제 Revision과 실제 작업자 확인 상태가 변경이력에 남는다.
- 로컬 업무이며 서버·로그인·다른 앱 장애와 관계없이 실행된다.
