# ORDER Q 재분석·파일 교체 작업값 보존

- 기준: PR #622 병합본 `5cd99df2b6ec57bf2cdbc2601b858e6f1b2f0c54`.
- 목적: 독립 연속작업 검사에서 발견된 두 작업 유실만 국소 교정. 기존 계산·수불·단위·NEXUS 교정은 유지.
- 변경 범위: 두 출고관리 HTML 진입점, 계산 엔진의 작업본 재계산/원본 참조 분리, 직접 회귀와 CI.
- 제외: 3영역, API/주문 묶음 확대, 공식 원장·저장 schema 변경, 타 앱 업무/UI 변경. 워크북 계산식은 변경하지 않음.

## 동작

1. 기본 **출고분석**은 현재 작업본 사본을 재계산하고 성공 시 교체한다. 수량·단가·공급가·재고 보정·구매처·대체 이력·참고 구매/판매 자료와 원본 근거를 유지한다.
2. 입력 파일 객체와 편집용 행/원본 행렬을 분리한다. 편집 순서에 따라 입력 자료가 오염되지 않는다.
3. 로컬/Cloud에서 복구한 작업본도 원본 파일을 다시 선택하지 않고 재분석할 수 있다. 기존 명시적 **현재 파일로 복구자료 교체**는 파일 기준 새 분석·검증 저장 경로를 유지한다.
4. 새 개별/자동분류/통합 Excel은 임시 후보에서 읽기·필수 열·행 오류 검사를 마친 후에만 교체한다. 실패·취소 시 기존 선택 자료·작업본·출력·복구 이력은 유지한다.
5. 통합파일의 정상 시트만 적용하고 잘못된 종류는 기존 입력을 유지하는 계약은 그대로다. 유효한 새 파일 교체는 기존처럼 이전 분석 결과를 비우고 새 분석을 준비한다. 서로 다른 원본에 이전 보정값을 자동 이월하지 않는다.
6. 읽기·분석 중 중복 실행/초기화를 차단한다. 작업 완료 또는 실패 후 다시 사용할 수 있다.

- 실제 Chromium에서 입력·수정·재분석·출력·IndexedDB 저장·새로고침 복구·읽기 실패를 연속 실행.
