# SmartInput 렌더 비용 수정

- 기준: PR #650 병합 `5315b63ef8b4ae443a7b01ee35687f3314fd57f0`.
- 목적: 반복 화면 갱신의 목록 DOM 생성·작업본 복제·작업대상 계산 비용 감소.
- 범위: SmartInput 표시 경로와 영향 검사. 저장·가격·매칭·전달·DB·공통 UI 계약 변경 금지.
- 실행/검증: 같은 담당자의 직접 검증이며 독립 PM 검증으로 표시하지 않는다.
- 완료조건: 동일 데이터에서 카드 유지, 선택/이름/순서/회사/로딩 상태 갱신, 작업본 보존,
  브라우저 성능 계측 및 관련 회귀·필수 CI 통과. 운영 업무자료에 테스트 쓰기 금지.
- 구현: 표시 필드가 변할 때만 목록 HTML 갱신, 원본 객체별 workspace adopt 중복 방지,
  날짜 포맷터 재사용, 작업대상 투영 입력 메모이제이션, 목록 hydrate의 전체 렌더 제거.
  설정/필드등록부 hydrate는 실제 표 구성이 바뀌므로 기존 전체 렌더를 유지한다.
- 잔여 범위: 최초 목록의 전체 DOM 생성은 유지한다. 실제 운영 데이터/장치의 전체 지연은
  합성 데이터 브라우저 측정으로 단정하지 않는다.

## 직접 검증

- Windows Chrome, 합성 견적서 1,000건, 같은 브라우저/프로필의 수정 전후 비교.
  반복 전체 렌더 10회 JS 실행 p95: 1,195.1 → 121.8ms (약 90% 감소).
  이는 동기 JS 실행 시간이며 전체 화면 표시 시간/실운영 KPI 완료 증거는 아니다.
- 같은 10회 동안 목록 DOM 생성 10 → 0, workspace 복제 10,000 → 0,
  작업대상 투영 계산 40 → 0. 선택·전체 선택·개별 해제·전체 해제와 카드 포커스 유지 확인.
- 1,000개 카드가 있는 상태에서 실제 입력 이벤트 30회 → 기존 snapshot의 다음 프레임
  p95 89.6ms. Long Task와 optional feature 계측도 결과 JSON에 보존한다.
- 이름/순서/본문 변경, 삭제, 타 회사 제외, 로딩 오류→복구, 파일 확인 상태,
  미저장 작업의 0 보존, 목록 hydrate의 입력 포커스 유지 통과.
- 기존 보호된 UI, 독립 복구, optional feature 경계, 3단계 계획 25건,
  Phase 6B 승인 UI, 가상 테이블 23건, 저장소 정적 검사 24건 통과.
- 실제 앱 브라우저의 견적서 격리 및 구매/판매/일반 주문/쇼핑 원본의
  자체 저장·목록·재열기·revision·보고서 검증 통과.
- 신규 성능 검사는 기존 5분 validate 작업에 더하지 않고 별도 병렬 CI로 실행한다.
  원격 CI 결과는 PR checks에서 최종 커밋과 대조한다.
