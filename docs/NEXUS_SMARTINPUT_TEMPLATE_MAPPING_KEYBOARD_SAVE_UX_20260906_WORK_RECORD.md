## 목적과 완료조건

신규 입력 양식의 추천 매핑을 확정 매핑과 명확히 구분하고, 추천 승인 및 검색 결과의 키보드 선택을 즉시 확정한다. 양식 저장이 차단될 때 관리자가 누락 항목을 일일이 찾지 않도록 문제 열만 필터링하고, 연결 대상과 중복 상대 열을 표시하며 첫 문제 열의 매핑 창을 자동으로 연다. 기본 입력 필드는 사용자가 지정한 10개 필드와 순서로 구성한다.

완료조건은 다음과 같다.

- 추천 상태가 승인 전 상태로 표시되고 승인 즉시 `MAPPED`와 `reviewed=true`로 저장된다.
- 검색창에서 Enter 또는 방향키로 결과에 진입하고 방향키 이동 후 Enter로 지정할 수 있다.
- 미승인 추천, 미결정, 중복, 삭제된 대상과 재검토 필요 상태를 구분해 정확한 열을 안내한다.
- 저장 검증 실패 시 문제 열만 남기고, 각 열을 확정할 때 남은 문제 열 목록을 즉시 갱신한다.
- 기본 입력 필드는 코드, 품명, 규격(기본), 수량, 단가, 공급가, 간단설명(품위), 지시사항, 출고가 (공지), 판매no. 순서로 표시한다.
- 원본 행·셀 값, 입력 양식 저장 계약과 기존 전표 투영 결과를 변경하지 않는다.
- 단위 테스트와 대표 브라우저 E2E가 통과한다.

## 현재 상태와 목표 상태

- 현재 운영 상태: 추천과 확정의 시각 구분이 약하고, 저장 실패 시 중복 또는 삭제된 대상이라는 일반 문구만 표시한다.
- 목표 상태: 관리자가 추천을 명시적으로 승인하고 검색 결과를 키보드로 지정하며, 저장 실패 원인을 해당 열에서 즉시 수정할 수 있다.

## 정책·경계

- 실행 방식: `LOCAL_OPERATION`
- SmartInput 화면, 입력 양식 매핑 검증과 기본 입력 필드 구성만 변경한다.
- IndexedDB 버전, Store, 데이터 마이그레이션, 공통 Runtime과 다른 앱 계약은 변경하지 않는다.
- 일반·다크 화면과 모바일 폭은 기존 공통 UI 토큰과 반응형 구조를 유지한다.
- 원격 최신 변경과 겹치는 SmartInput 소스는 최신 `origin/main`에 재기준화한 뒤 회귀검증한다.
