# SmartInput F8 중복 품목 가격 확정 작업 기록

## 목적

- 견적서 F8 출력에서 같은 품목코드가 여러 거래처 원본에 있을 때 코드만 표시하고 중단하던 흐름을 작업 가능한 검토 흐름으로 바꾼다.
- 입고가(견적단가)를 가격 산출 기준으로 사용하고 거래처별 견적 거래행은 보존한다.

## 구현 계약

1. 선택 견적의 병합 전 원본행을 품목코드로 그룹화한다.
2. 중복 그룹은 거래처, 원본 Excel 행번호, 창고, 품명·규격, 입고가, 계산 출고가를 한 화면에 표시한다.
3. 사용자는 각 그룹에서 기존 행 하나를 대표로 선택하거나 그 행의 입고가를 이번 출력에 한해 직접 수정한다.
4. 모든 그룹이 확정되기 전에는 통합업로드용 Excel을 생성하지 않는다.
5. 확정 뒤 `쇼핑몰업로드`와 `ERP업데이트`는 품목코드당 대표 상품행 하나를 출력한다.
6. 마지막 `견적서 업로드`는 거래처별 원본 거래행을 삭제하지 않고 모두 유지하며 거래처명 → 품목코드 순으로 정렬한다.
7. 매핑 기반 견적의 ERP 출고가, 쇼핑몰 시중가, 견적서 업로드 단가는 입고가·외주비·노무비와 Settings 마진룰로 계산한다. 양수 행사가와 사용자가 명시적으로 편집한 가격의 기존 우선권은 유지한다.
8. 선택·직접 수정은 보고서 생성용 결정이며 원본 견적서, Settings, 상품 Master에는 쓰지 않는다.

## 원본 파일 검증

로컬 참조 파일 `견적서현황.xlsx`는 수정하거나 저장소에 추가하지 않았다. `견적서현황내역`에서 다음 중복 3개 그룹을 확인했다.

| 품목코드 | 원본 행 | 거래처 | 입고가 |
| --- | --- | --- | --- |
| 104524112 | 131, 132 | 가락(청산유통), 농협 | 공란, 공란 |
| 105522110 | 210, 211 | 초원, 농협 | 10,000, 11,000 |
| 105524122 | 217, 218 | 초원, 농협 | 12,000, 공란 |

세 그룹에 대표 결정을 제공하면 중복 오류 없이 출력 모델을 생성함을 확인했다. 상품 Snapshot이 필요한 소분 상품 검증은 운영과 동일하게 Product Snapshot을 제공한 상태에서 통과한다.
