## 결과 계약

- 견적 보고서: `쇼핑몰업로드` → `ERP업데이트` → 조건부 `확인요청` → `견적서 업로드`
- 구매 보고서: `확인요청` → `판매입력` → `전송출고` → `전송구매` → `거래처별` → `단가설정` → `구매 업로드`
- 견적 쇼핑몰 판매여부는 원본 출고가가 양수면 1, 아니면 0이다.
- 견적 쇼핑몰 재고수량은 모든 본품·소분품에서 999다.
- 견적 ERP업데이트는 `품목코드, 입고가, 0, 출고가, 0, 입고B, n, 도매A, n, 도매B, n`의 11열만 생성한다.
- 견적서 업로드는 사용자 지정 19열, 구매 업로드는 사용자 지정 20열을 정확한 순서로 생성하고 각각 마지막 시트로 둔다.

## 구매 판매업로드 알고리즘

- 청과상장: `출고가(공지) > 청과 > 도매A/0.91 > 상장가`
- 식자재: `출고가(공지) > 식자재 > 도매A > 출고(외노)`
- 창고출고: `출고가(공지) > 도매A > 출고(외노)`
- 내부이동: `단가`
- 수량 0은 단가·공급가 0, 음수는 반품 부호 유지, 잘못된 수량은 업로드 제외다.
- 단가누락·그룹누락·역마진·도매A 과대입력은 자동 보정하지 않고 확인요청으로 남긴다.
- 불러온 원본은 `inputMapping.sourceMatrix`를 사용하며 화면의 명시 수정값만 덮어쓴다.
