## 1. 목적과 전제

좌측에서 Excel 자료 준비와 매핑을 끝내고, 중앙에서는 출고 판단과 수정에 집중할 수 있도록 한다. 정상 매핑 파일은 불러오는 즉시 처리해 중앙에 표시하며, 확인이 필요한 파일만 좌측에서 보완한다.

ONEAPP NEXUS와 각 업무 앱은 관리자의 판단을 위한 작업대이며 결정권은 관리자에게 있다. 이 공통 규범을 전제로 하되, 일상 입력마다 별도 승인 단계나 반복 안내를 추가하지 않는다. NEXUS의 기존 헤더·테마·앱 이동·공통 설정 기준을 유지한다.

이번 변경의 핵심은 다음 세 가지다.

1. 시안에 맞춘 좌측 자료 선택·파일 불러오기 배치.
2. 파일·시트·항목 매핑을 같은 위치에서 확인하고 수정.
3. 정상 자료는 추가 실행 클릭 없이 중앙 표시까지 연결하고, 실패하면 기존 작업 보존.

## 2. 범위

| 구분 | 내용 |
|---|---|
| 구현 | 좌측 자료 종류 선택, 드롭 영역, 파일 목록, 두 매핑 아코디언, 양식 재사용, 정상 파일 즉시 표시 |
| 국소 교정 | 창고 헤더·시트 별칭 등 실제 입력 실패의 재현과 수정, 파일 처리 완료까지 작업 보존 |
| 유지 | 중앙 작업표·기존 우측 기능, 조회·필터·셀 편집·단축키, 계산·저장·복구·인쇄·Excel 출력 |
| 제외 | 전체 3영역 재구축, API 확대, 신규 주문 묶음·다중 원본 병합, 공식 전표·원장 변경, 타 앱 개편, NEXUS 공통 구조 변경 |

기존 여러 자료 종류 불러오기·통합 Excel 입력은 호환 범위로 유지한다. 이를 여러 주문을 하나로 합치는 새 기능으로 확장하지 않는다. `수불현황`은 계산·조회 결과이며 다섯 번째 업로드 자료 종류가 아니다.

## 3. 시안 적용과 좌측 구성

![사용자 제공 좌측 자료 준비 시안](assets/orderq-left-excel-mapping-reference-2026-09-17.png)

시안은 좌측 상단의 배치·계층·표현을 기준으로 사용한다. 첨부 이미지의 잘린 폭을 실제 화면의 고정 폭으로 적용하지 않는다. 중앙·우측의 기존 기능을 재배치하지 않는 범위에서 좌측 폭과 내부 스크롤을 조정한다.

| 순서 | 구성 | 동작 |
|---|---|---|
| 1 | 2×2 버튼: `주문서 / 구매`, `판매 / 재고` | 불러올 자료 종류 선택. 선택 상태를 테두리·배경·문자로 구분 |
| 2 | 점선 테두리 파일 드롭 영역 | Excel 아이콘, 드래그·클릭 안내, 영역 내부의 `엑셀 불러오기` 버튼 |
| 3 | 불러온 파일 목록 | 파일명·자료 종류·처리 상태·건수·선택·제거 |
| 4 | `① 파일·양식 확인` 아코디언 | 파일명, 양식명, 자료 종류, 시트, 항목명 행, 자료 범위, 원본 미리보기 |
| 5 | `② 항목명 매핑` 아코디언 | 원본 열과 작업 항목 연결, 사용·제외, 창고 수량 열 지정 |
| 6 | 설정 행동 영역 | `매핑 저장`, 보완 중인 자료의 `자료 반영`, 현재 상태 안내 |

표현 기준:

- 시안의 문구는 `엑셀 파일을 여기에 드래그하거나 클릭하여 불러오세요.`와 `엑셀 불러오기`를 사용한다. 지원 확장자는 `.xls, .xlsx`로 표시한다.
- 네 버튼은 API 메뉴나 중앙 조회 탭이 아니다. 종류 전환만으로 파일을 적용하거나 기존 중앙 작업을 비우지 않는다.
- 선택 종류는 강조하고 나머지는 낮은 강조도로 표시한다. 자료 종류별 아이콘은 시안을 따른다.
- 정상 반영 파일은 저채도 상태색과 건수, 미반영은 중립색, 문제는 `시트 확인 필요`·`항목 2개 미확인`처럼 이유를 표시한다. 색상만으로 상태를 구분하지 않는다.
- 정상 파일은 아코디언을 열지 않아도 사용할 수 있다. 문제가 있는 그룹만 자동으로 열고 해당 항목을 표시한다.
- 파일을 바꾸면 두 아코디언이 해당 파일의 설정으로 바뀐다. 접기·펼치기·파일 선택 전환으로 편집 중 설정을 잃지 않는다.
- 좁은 화면에서는 좌측 내부 스크롤을 사용하고 버튼·입력값이 잘리지 않게 한다. 기존 NEXUS 밝은/어두운 테마를 지원한다.

## 4. 파일 불러오기와 중앙 즉시 표시

### 4.1 정상 매핑 자료

`자료 종류 선택 → 파일 불러오기 → 읽기·검증·필요 계산 → 중앙 표시`

- 기존 저장 매핑 또는 정상 파서 인식 결과가 있고 구조 검증을 통과하면 자동 진행한다.
- 정상 파일에 `자료 반영`, `출고분석`, Enter 입력을 추가로 요구하지 않는다. 매핑 저장도 매번 요구하지 않는다.
- 업로드한 자료에 맞는 표를 바로 표시한다: 주문서 → 주문현황, 재고 → 창고재고, 구매 → 구매현황, 판매 → 판매현황. 자료가 모두 준비됐다는 이유로 주문현황에 강제 전환하지 않는다.
- 주문만 준비된 경우에도 조회 가능한 주문행은 표시하고, 재고가 필요한 값만 미확인으로 둔다. 미확인 재고를 0으로 바꾸거나 부족량을 확정된 값처럼 계산하지 않는다.
- 구매·판매·재고만 읽은 경우에는 해당 자료의 조회 가능한 내용을 표시한다. 존재하지 않는 주문을 만들지 않는다.
- 자료를 읽는 순서를 강제하지 않는다. 추가 자료가 준비되면 계산 가능한 항목을 기존 산식으로 갱신한다.
- 자료 처리와 화면 선택은 분리한다. 표는 작업자가 정보를 보고 편집하는 화면이며 이후 조회 탭·열 순서·열 표시·양식 선택은 기존 사용자 조작을 유지한다. 여러 자료 종류 동시 입력은 지정된 우선 자료(없으면 첫 번째 파일)의 표를 초기 표시한다.
- 기존 작업이 있고 새 후보 자체의 필수 매핑·구조에 오류가 있으면 중앙은 기존 작업을 유지한다. 이는 정상 주문 파일은 있지만 재고 파일은 아직 없는 경우와 구분한다. 다른 종류 자료의 미준비만으로 정상 파일의 조회를 막지 않는다.

### 4.2 확인이 필요한 자료

`파일 불러오기 → 문제 표시 → 좌측에서 수정 → 자료 반영 → 중앙 표시`

- 종류·시트·필수 항목의 연결이 모호하거나 구조가 맞지 않을 때만 보완 경로를 사용한다.
- 수정 과정과 원본 미리보기는 중앙 작업을 바꾸지 않는다.
- `자료 반영`은 수정한 매핑을 현재 파일에 적용하는 행동이다. 성공하면 필요한 처리와 중앙 표시까지 이어지며 다시 분석 버튼을 누르지 않는다.
- 같은 파일을 다시 올릴 필요가 없도록 현재 후보의 원본 bytes 또는 raw/display 행렬을 임시 보관한다.
- 여러 자료 종류 동시 입력이 실패해도 선택한 각 파일과 미결정 매핑을 좌측에 보존한다. 중앙은 기존 작업을 유지하며 후보별 보완 후 반영할 수 있다. 같은 종류 후보의 보관은 자동 병합을 뜻하지 않는다.
- 오류가 남으면 해당 부분과 이유를 표시하고 기존 작업을 유지한다. 관계없는 조회·편집까지 막지 않는다.

### 4.3 두 저장 행동의 구분

| 행동 | 의미 |
|---|---|
| `매핑 저장` | 양식명과 연결 설정을 다음 파일에도 재사용하도록 저장. 현재 중앙 작업 자체를 교체하지 않음 |
| `자료 반영` | 보완한 현재 파일을 검증·처리하여 작업에 적용. 정상 자동 반영 파일에는 추가 클릭을 요구하지 않음 |

보완한 파일을 반영할 때 양식 저장을 선행조건으로 요구하지 않는다. 이미 반영된 파일은 변경사항이 없으면 `반영 완료 · N건`을 표시한다. 저장된 작업·출력의 기존 명령과 이 두 행동을 혼합하지 않는다.

## 5. 파일·시트·항목 매핑 계약

### 5.1 파일·양식 확인

| 항목 | 명세 |
|---|---|
| 원본 파일명 | 그대로 표시·보존. 유형 판단의 단서일 뿐 단독 확정 근거로 사용하지 않음 |
| 자료 종류 | 주문서·구매·판매·재고. 사용자가 지정한 종류와 구조가 충돌하면 이유를 표시 |
| 양식명 | 재사용 설정의 이름. 날짜가 포함된 원본 파일명과 분리 |
| 시트 | 실제 workbook의 시트 목록에서 선택. 저장 별칭과 실제 항목 구조를 함께 확인 |
| 항목명 행 | 원본 행 번호로 지정. 상단 제목·설명 행과 구분 |
| 자료 범위 | 시작·끝 행을 원본 좌표로 표시·수정. 범위 밖 행을 작업에 섞지 않음 |
| 원본 미리보기 | 선택 시트의 원본 표시값과 좌표를 보여주고 연결 결과와 대조 가능하게 함 |

현재 개별 입력·자동 분류·통합 파일의 판정 경로를 무조건 하나의 우선순위로 바꾸지 않는다. 개별 종류 지정, 구조 기반 분류, 저장 시트 별칭을 각각 해당 경로에서 재사용한다. 파일명만으로 선택하거나 필수 열이 없는 시트를 별칭 때문에 정상으로 취급하지 않는다.

통합 파일의 안내·설명 시트는 제외할 수 있다. 정상 업무 시트와 잘못된 시트를 구분해 기존 입력의 해당 종류만 안전하게 처리한다. 같은 종류의 후보 시트가 여러 개이고 기존 설정으로 하나를 결정할 수 없으면 좌측에서 선택하게 하며, 마지막 시트로 조용히 덮어쓰거나 새 병합을 수행하지 않는다.

### 5.2 항목명 매핑

각 원본 열은 `열 위치·원본 항목명·연결할 작업 항목·사용 여부`를 가진다. 같은 이름의 열이 여러 개일 수 있으므로 항목명 문자열만으로 식별하지 않는다.

- 작업 항목은 현행 파서가 지원하는 종류별 항목을 사용한다: 상품코드·품명·규격·단위·수량·단가·금액·거래처·일자 등.
- 필수 여부는 기존 종류별 검증을 재사용한다. 새 공통 필수 항목을 일괄 강제하지 않는다.
- 필수 항목 누락, 같은 작업 항목의 모호한 중복 연결, 유효하지 않은 범위는 해당 파일에서 설명한다.
- 일반 자동 인식·저장 양식·수동 반영 모두 동일 매핑 검증을 통과해야 한다. 같은 이름의 수량 두 열 중 첫 열을 임의로 선택해 정상 처리하지 않는다.
- 미사용 열은 `제외`로 지정할 수 있으며 원본을 삭제하지 않는다.
- 열 순서가 바뀐 새 파일에서는 저장된 열 번호를 그대로 적용하지 않는다. 항목 구조를 다시 대조해 유일하게 연결되면 재사용하고 모호하면 확인 대상으로 둔다.
- 숫자 0, 문자열 `'0'`, 공란, 음수, 소수, 앞자리 0이 있는 코드를 임의로 서로 치환하지 않는다. raw 값과 표시값을 기존 파서·출력 계약대로 보존한다.
- 단위가 다른 값을 매핑 단계에서 합산하거나 자동 환산하지 않는다.

### 5.3 창고 열

- 엔진의 창고 열 판정 결과와 원본 열 위치를 우선 사용한다. 화면에서 이름만 보고 별도의 추측 로직을 만들지 않는다.
- `신선A`, `본사`처럼 이름에 ‘창고’가 없는 수량 열도 지정·유지할 수 있다.
- 총재고·단가·전송단가·메모 같은 열을 창고 수량에 합산하지 않는다.
- 창고 이름과 출고 배정 역할·우선순위는 구분한다. 새 창고 열을 매핑했다고 기존 배정 규칙을 자동 변경하지 않는다.
- 검증 예: 총수량 12, `1창고=2`, `신선A=4`, `본사=6`을 모두 보존하고 기존 합계 검증이 12를 확인한다. 공란을 0으로 채워 검증을 통과시키지 않는다.

## 6. 파일 목록·설정 저장·호환성

- 파일 목록은 현재 준비한 자료를 확인하는 목록이며 새 주문 묶음 저장소가 아니다. 동일 종류의 새 입력은 기존의 교체 범위로 처리한다.
- 동일 파일명이더라도 다른 입력·시트를 잘못 연결하지 않도록 세션의 파일 식별자와 시트·열 좌표를 사용한다. 파일명만을 고유키로 사용하지 않는다.
- 미반영 후보 제거는 해당 후보만 목록에서 제거한다. 반영 자료를 해제할 때는 대상과 작업 영향을 구분하고, 기존 디스크 파일·복구 이력까지 삭제하지 않는다.
- 기존 `oneapp.orderops.excel-mappings.v1` / `orderops-excel-mappings/v1`의 종류별 파일·시트·열 별칭을 읽어 그대로 사용할 수 있어야 한다.
- 양식명·항목명 행·범위·열별 연결처럼 기존 별칭 레코드로 표현할 수 없는 설정만 ORDER Q 소유의 소규모 양식 설정으로 추가한다. 기존 레코드를 파괴적으로 변환하거나 새 공통 DB를 만들지 않는다.
- 별칭의 종류 간 충돌은 기존 검증을 유지한다. 설정 저장 실패는 성공으로 표시하지 않고 이전 저장 설정을 보존한다.
- 원본 파일과 미확인 매핑 초안은 작업본과 분리한다. 새 UI가 없던 시기의 복구 자료도 파일 재선택·새 매핑 없이 열 수 있어야 한다.
- 활성 작업의 복구 원본과 미반영 후보를 파일 목록에 함께 표시한다. 실패 후보를 추가하거나 제거해도 활성 원본 목록은 남는다.
- `shipping-workspace/v2`, `orderops-analysis-inputs/v1`, 기존 로컬 복구·Cloud 저장 계약은 변경하지 않는다. 새 양식 저장은 기존 작업 복구의 필수조건이 아니다.

## 7. 작업 보존과 자동 처리 경계

처리는 `임시 후보 읽기 → 구조·매핑 검증 → 후보 계산/표시자료 생성 → 성공한 결과 교체` 순서로 수행한다. 활성 입력과 작업본을 미리 지우지 않는다.

1. 읽기·파싱·검증·계산 실패 또는 파일 선택 취소 시 이전 입력, 중앙 작업값, 출력 가능 상태, 복구 포인터를 유지한다.
2. 읽기·반영 중에는 기존 실행 잠금을 재사용해 중복 업로드·초기화·상충하는 반영을 막는다. 완료·실패 후 해제하며 늦게 끝난 이전 요청이 최신 작업을 덮지 않게 한다.
3. 기존 작업의 기본 재분석은 현재 수정값을 재계산하는 PR #623 동작을 유지한다. 매핑 보기·파일 선택·아코디언 조작으로 원본 재분석을 실행하지 않는다.
4. 새 파일 교체는 후보 원본을 사용한다. 기존 작업본 재계산 함수를 그대로 호출해 새 파일이 무시되는 구현을 하지 않는다.
5. 교체 범위는 자료 종류별로 제한한다. 재고 파일 교체 때문에 기존 주문의 수정 수량·단가·구매처를 원본으로 되돌리지 않는다. 구매·판매 참고 자료 교체도 주문·재고의 수정값을 초기화하지 않는다.
   재고 해제 → 재입력도 같은 보존 기준을 적용한다. 유지한 주문의 구매처·수량·단가는 남기고, 해제한 재고의 보정은 새 재고에 이월하지 않는다.
6. 교체 대상 자체의 원본 종속 보정은 새 파일에 임의로 이월하지 않는다. 예를 들어 이전 재고 파일에 대한 보정은 새 재고 원값을 덮지 않는다. 교체하지 않은 자료와 작업값은 유지하며, 같은 자료의 단순 재계산은 기존 수정값을 보존한다. 새로운 원본 간 행 병합·추정 매칭을 도입하지 않는다.
7. 정상 반영 이후 로컬 작업 저장은 기존 안전 저장 경로를 사용한다. 저장 실패 시 이전 정상 복구 자료를 유지하고 미저장 상태를 명확히 표시한다.
8. 양식 편집과 자료 표시를 이유로 Cloud 쓰기·타 앱 데이터 갱신·공식 원장 명령을 새로 연결하지 않는다.

### 12.1 PR #624 추가 반례 보완

사용자의 추가 검증 네 경로와 자료별 조회 요구를 같은 브랜치에서 보완했다. 주문 업로드는 주문현황, 재고 업로드는 창고재고, 구매·판매 업로드는 각각 해당 조회표를 표시한다. 조회 탭·열·양식은 작업자가 선택하며, 주문과 재고가 모두 있다는 이유로 주문현황으로 강제 전환하지 않는다.

- 일반 자동 파싱에도 같은 매핑 검증을 적용한다. 중복 수량 열은 확인 후보로 남고, 좌측에서 제외 열을 선택한 뒤에만 선택한 수량을 반영한다.
- 여러 자료 종류 파일의 자동분류가 실패하면 모든 탐색이 끝난 뒤 원본·시트·매핑 초안을 후보로 보존한다. 중앙 작업은 바꾸지 않고 재업로드 없이 보완한다.
- 재고 해제 후 다시 불러와도 유지한 주문의 수정 수량·단가·구매처·이력을 보존한다. 새 재고에는 해제한 재고의 보정값을 넘기지 않는다.
- 복구한 활성 원본과 새 미반영 후보를 함께 표시한다. 후보 추가·제거가 복구 원본 목록을 숨기지 않는다.
