# SmartInput 거래처별 견적 저장 차단 빠른 수정 작업기록

## 증상

- 연동견적서를 연 뒤 ERP 견적서현황을 매핑하고 거래처별 견적서 업데이트를 열면, 모든 대상이 `확인 필요`가 되어 저장 버튼이 비활성화됐다.
- 화면에는 현재 연동견적서 자체의 작업본을 가리켜 `연동견적서에 저장하지 않은 작업본이 있습니다`라고 표시됐다.

## 원인과 수정

- ERP 갱신 입력으로 사용 중인 현재 견적서 작업본까지 일반적인 별도 미저장 작업 충돌 검사에 포함돼 자기 자신을 순환 차단했다.
- 거래처별 갱신 계획에 현재 열린 견적서 ID를 명시해 그 작업본만 충돌 대상에서 제외했다.
- 다른 개별·연동견적서의 미저장 작업본은 기존처럼 저장을 차단한다.
- 저장된 입력 양식은 동일한 회사·전표 종류·열 구성에서 자동 적용되며, 양식 저장 완료 문구에 다음 동일 열 구성 자동 적용 사실을 명시했다.
- 정확한 ERP 23열 견적서현황으로 인식된 원본은 A~F 필수값이 모두 있는 행만 입력 상품으로 투영한다. 생성시각 한 셀만 있는 마지막 시스템 푸터는 원본 증적에 보존하되 상품에서는 제외한다.

## 계약

- IndexedDB Store와 저장 schema는 변경하지 않는다.
- 거래처별 원자적 저장, 다른 거래처 독립 처리, 미저장 타 작업본 보호 정책을 유지한다.
- SmartInput module cache token은 `0.11.31`, 거래처별 갱신 core token은 `0.2.1`이다.

## 검증

- 실제 `견적서현황.xlsx` 업로드: `견적서현황내역 · 거래처 10곳 · 품목 277개 · 원본 280행`, 생성시각 푸터 상품 제외 확인
- 거래처별 업데이트 단위·브라우저 E2E 통과: 현재 연동견적서 자기 충돌 제외, 다른 미저장 작업본 보호, 거래처별 부분 실패 롤백
- 입력 양식 브라우저 E2E 통과: 저장된 동일 열 구성 자동 적용
- SmartInput 전체 데스크톱·모바일 브라우저 E2E 및 독립 복구·설정·보호 워크스페이스 계약 통과
