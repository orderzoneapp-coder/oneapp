공통 모듈은 모든 표를 편집 가능하게 만들지 않는다. 앱 자체 열폭 구현이 있는 SmartInput·OrderOps·MerchOps·DataOps에서는 중복 핸들을 생성하지 않는다. 앱 자체 열 메뉴가 있는 OrderOps 중앙표는 해당 검색·필터·정렬을 재사용한다. React 소유 표는 내부 DOM 삽입·재정렬이 연속 연결과 편집 state를 훼손하므로 공통 메뉴를 삽입하지 않고 앱 소유 검색·필터·정렬·열 설정을 보존한다. 그 밖의 표는 공통 메뉴가 DOM 표시 순서·노출만 바꾼다. 같은 열 선택값은 OR, 서로 다른 열은 AND이며 해제 시 원래 행 순서와 공란·0·음수·소수·선행 0 텍스트를 그대로 복원한다.

| 예외 화면 | 공통 모듈이 하지 않는 조작 | 업무상 이유 | 대신 제공하는 조작 |
|---|---|---|---|
| 상품관리·스마트파서·MerchOps·DataOps의 React 소유 표 | 헤더 자식 삽입, DOM 행 재정렬 | React의 안정 행 key와 연결·검토·가격·검산 state를 보존해야 함 | 각 앱의 기존 검색·상태/분류 필터·정렬·열 설정을 유지하고 공통 팔레트·인쇄 계약만 적용 |
| 출고관리 중앙 작업표 | 공통 열 메뉴·열폭 손잡이 중복 생성 | 안정 행 ID 기반 편집, 열 preset과 출력 계약을 앱이 소유 | 기존 열별 OR·열간 AND 필터, 정렬, 검색, 열순서·표시·폭 기능 사용 |

## 출고관리 데이터 계약

- 고객 키 우선순위: 기존 `customerKey` → `customerId|customerCode` → 거래처명+주문/그룹 배송 단위 → 원본 행.
- Excel 선택 열: `거래처코드|고객코드|거래처ID|고객ID`, `지역|배송지역|배송권역|권역`.
- 직원 메모: `적요1|적요(직원)|직원적요`; ORDER Q는 line `description`. 일반 `적요`는 사용하지 않는다.
- 배송건 집계: 고객 키+창고+주문번호/그룹 1건. 상품행 수와 무관하다.
- 혼합 담당자: 명시적 재배정 전 `혼합(...)`으로 표시하고 자동 통일하지 않는다.
- 담당자 재배정: 검색 가능한 datalist와 자유입력. 같은 고객 키의 현 작업공간 주문행만 변경하고 행별 system history를 남긴 뒤 기존 임시저장 예약을 실행한다.
- 우측 재고: `getInventoryViewRows()`의 현재 메모리 Read Model만 소비한다. `현재 재고`, `주문수량`, `예상 잔량`, append-only 출고결과의 `실제 출고 확정`을 별도 표시한다.

## 상태·복구·출력 경계

- 패널과 열폭 변경은 로컬 UI preference만 저장한다. 분석·서버 동기화·업무 저장을 호출하지 않는다.
- 오른쪽 닫기/열기는 DOM과 선택 상품 내용을 유지하며 마지막 선호 폭은 공통 workbench 저장키에서 복원한다.
- 960px 이하는 왼쪽·중앙·오른쪽 순으로 쌓고 모든 영역 접근을 유지한다. 저장 선호 폭을 작은 화면 값으로 덮지 않는다.
- 일반/흰색 인쇄는 `#FFFFFF`; 선택·hover·focus 배경은 제외하고 기존 창고/담당자 의미색 인쇄 정책은 앱 출력 코드가 계속 소유한다.
