## 1. 목적

SmartInput의 기존 파서창을 `원본입력뷰`로 명칭 변경하고 Excel 자료에 대해 다음 두 공통 기능을 제공한다.

1. 원본 행 중 필드명 행을 지정한다.
2. 파일의 각 열을 SmartInput 환경설정 필드에 매핑하거나 비매핑으로 확정한다.

매핑 프로세스는 주문서·구매·판매·견적서에서 공통으로 사용한다. 전표별 필수항목 검증, 전표 분리, 저장과 전달은 기존 전표 프로세스가 계속 담당하며 이번 매핑 완료 조건에 포함하지 않는다.

## 2. 보존 범위

- 기존 원문 텍스트·이미지·OCR·음성 입력
- 기존 3분할 작업영역과 공통·앱 헤더
- 고정 전표 저장 구조와 주문·구매·판매·견적 저장 계약
- 상품 검색·매칭, 행 편집·추가·삭제·선택·검색·합계
- 자동저장·복구, 카톡 공유, Excel 출력
- 기존 공개 localStorage 키와 다른 앱 소유 저장소 경계
- 마지막 수기입력 빈 행

SmartInput은 다른 앱의 원시 저장소를 직접 쓰지 않는다.

## 3. 용어

| 용어 | 의미 |
|---|---|
| 원본입력뷰 | 기존 파서창. Excel 원본 행·열·값·순서를 변경하지 않고 확인하는 영역 |
| 필드명 행 | 원본에서 열 이름으로 사용할 한 행 |
| 파일 구조 | 필드명 원문 배열의 개수와 순서 |
| 입력 양식 | 파일 구조와 열별 설정 필드 ID 또는 비매핑 결정을 저장한 규칙 |
| 완벽 일치 | 필드명 원문·필드 개수·열 순서가 저장 양식과 모두 동일한 상태 |
| 추천 매핑 | 신규 양식에서 파일 필드와 설정 필드가 각각 하나일 때 제안하는 미확정 연결 |
| 매핑 완료 | 모든 열 결정과 대상 무결성을 통과하고 관리자가 신규 양식으로 저장한 상태 |

## 4. 데이터 계층

Excel 작업은 다음 계층을 분리한다.

1. `sourceMatrix`: 불러온 원본 행렬. 현재 작업 중 수정하지 않는다.
2. `headerRowIndex`: 사용자가 지정한 필드명 행 위치.
3. `workingRows`: 필드명 아래 데이터를 원래 열 순서로 표시하는 편집 복사본.
4. `columnMappings`: 열 위치별 설정 필드 ID 또는 `UNMAPPED` 결정.
5. 기존 전표 행: 매핑된 필드만 기존 SmartInput 전표 데이터로 투영한 결과.

필드명 행 재지정은 원본을 변경하지 않고 서명·양식 판정·작업테이블을 다시 계산한다. 편집값은 원본 행·열 좌표 기준으로 보존한다.

## 5. 원본 불러오기와 필드명 행

- 파일 선택, 끌어놓기와 붙여넣기를 지원한다.
- Excel의 제목행·공란·행·열·값·순서를 임의로 삭제하거나 재배치하지 않는다.
- 시스템은 필드명 후보 행 하나를 표시한다.
- 관리자는 원본입력뷰의 행 번호를 눌러 필드명 행을 즉시 다시 지정할 수 있다.
- 별도 `작업테이블 적용` 버튼이나 확인 단계는 두지 않는다.
- 분석 성공 전에는 현재 작업을 변경하지 않는다.
- 성공 시 현재 작업의 직전 상태를 붙여넣기 취소용으로 한 번 보존한다.
- 파일 불러오기 성공 시 기존 상단 입력값은 초기화한다.

## 6. 양식 판정 알고리즘

필드명 행의 셀 원문 배열을 다음 순서로 비교한다.

1. 필드 개수
2. 각 필드명 원문
3. 각 필드의 열 위치

정규화, trim, 별칭, 유사도, 파일명, 시트명과 사용횟수는 완벽 일치 판정에 사용하지 않는다. 같은 이름의 열이 여러 개여도 열 위치로 구분한다.

### 6.1 완벽 일치

- 저장된 입력 양식의 열별 매핑을 그대로 적용한다.
- 설정 필드 ID가 삭제됐거나 중복 연결돼 있으면 정상 적용으로 위장하지 않고 `INVALID_TEMPLATE`로 표시한다.
- 전표 저장을 차단하고 양식관리에서 재연결하도록 한다.
- 수정 후 파일을 다시 올리지 않는다. 현재 원본·편집값을 유지하고 양식 정보만 다시 불러와 재검증한다.

### 6.2 불일치

- 기존 양식을 수정하거나 유사 양식으로 추정하지 않는다.
- 무조건 신규 양식 설정 상태로 시작한다.
- 파일 필드명과 설정 필드 표시명이 원문 기준으로 각각 정확히 하나일 때만 추천 매핑한다.
- 파일 쪽 또는 설정 쪽에 같은 표시명이 둘 이상이면 추천하지 않는다.
- 추천은 관리자 저장 전까지 확정 매핑이 아니다.

## 7. 직접 매핑

- 작업테이블 필드명 버튼을 누르면 매핑 모달을 연다.
- 현재 SmartInput 환경설정의 상단·하단 기본 필드와 사용자 생성 필드를 검색한다.
- 설정 필드를 누르면 해당 열에 즉시 연결한다.
- `비매핑`을 누르면 해당 열은 표시·편집하되 전표 투영에서 제외한다.
- 설정 필드 ID 하나에는 파일 열 하나만 연결할 수 있다.
- 다른 열이 이미 사용한 대상은 선택할 수 없고 사용 중인 열을 표시한다.
- 비매핑 열과 미결정 열을 시각적으로 구분한다.

## 8. 신규 양식 완료와 저장

신규 양식 완료 조건은 다음 네 가지뿐이다.

1. 모든 파일 열이 `MAPPED` 또는 `UNMAPPED`로 결정됨
2. 하나의 설정 필드 ID에 파일 열이 중복 연결되지 않음
3. 연결된 설정 필드 ID가 현재 환경설정에서 유효함
4. 관리자가 양식명을 지정하고 신규 양식으로 저장함

전표 필수정보와 전표 저장 가능 여부는 양식 완료 조건이 아니다.

입력 양식에는 다음만 저장한다.

- 양식 ID·양식명·revision
- 필드명 원문 배열, 필드 개수와 열 순서
- 열 위치별 설정 필드 ID 또는 비매핑 상태
- 생성·수정 시각

상단 추가정보, 작업 데이터, 열 숨김, 파일명과 시트명은 저장하지 않는다. 동일 구조의 공식 양식은 하나만 허용한다.

## 9. 양식관리 경계

- 기존 양식의 이름·매핑·비매핑 변경과 삭제는 환경설정의 `입력 양식 관리`에서만 수행한다.
- 작업테이블은 기존 양식을 수정하지 않는다.
- 양식관리 변경은 다음 파일부터 적용한다.
- 현재 열어 둔 파일에는 관리자가 `양식 다시 불러오기`를 실행할 때만 적용한다.
- 새 revision이 현재 편집값을 자동 덮어쓰지 않는다.

## 10. 작업테이블

- 지정된 필드명과 원본 열 순서로 모든 파일 필드를 표시한다.
- 매핑 여부와 관계없이 모든 셀을 조회·편집할 수 있다.
- 비매핑 값은 전표 투영에서만 제외한다.
- 열 숨김은 현재 화면 보기 상태이며 입력 양식에 저장하지 않는다.
- 기존 검색·행 추가·행 삭제·선택·합계·키보드 편집을 유지한다.
- 작업 처음부터 마지막 수기입력 빈 행 하나를 유지한다.
- 원본입력뷰는 바뀌지 않고 작업테이블만 편집한다.

## 11. 전표 프로세스와의 경계

매핑 엔진의 출력은 설정 필드 ID를 키로 하는 편집 데이터다. 기존 전표 어댑터가 이를 기존 전표 행으로 변환한다.

- 주문서·구매·판매·견적서는 각자의 기존 필수항목과 저장조건을 유지한다.
- 양식이 유효해도 전표 필수값 부족으로 전표 저장이 실패할 수 있다.
- 현재 전표에 필요한 필드가 없어도 입력 양식은 저장할 수 있다.
- 상단 추가정보, 다중 전표 분리와 저장 차단은 기존 전표 프로세스의 책임이다.
- 기존 전표 payload와 저장소 계약을 변경하지 않는다.

## 12. 작업테이블 직접 붙여넣기

- 현재 표시된 필드명 원문·개수·순서와 붙여넣은 첫 행이 완전히 같을 때만 여러 셀을 적용한다.
- 하나라도 다르면 적용하지 않고 현재 작업을 유지한다.
- 원본입력뷰로 자동 이동하지 않는다.
- 사용자가 명시적으로 `원본입력뷰에서 확인`을 선택할 때만 방금 붙여넣은 자료를 전달한다.
- 단일 셀 편집은 기존처럼 허용한다.

## 13. 저장소

- DB 이름과 version은 기존 `oneapp-smartinput` v4를 유지한다.
- 기존 `settings` Store의 additive KV `inputTemplates`에 입력 양식 목록을 저장한다.
- IndexedDB가 없는 환경에서는 기존 SmartInput fallback 객체의 같은 키를 사용한다.
- 기존 Store, localStorage 키와 공개 계약을 변경하지 않는다.

## 14. 오류와 보존

- 파싱 실패: 현재 원본·작업테이블·선택·관리자 편집값 유지
- 양식 조회 실패: 정상 0건으로 표시하지 않고 `ERROR`
- 일치 양식 중복: 자동 선택하지 않고 오류
- 삭제된 대상·중복 대상: 기존 양식 무효, 전표 투영 차단
- 신규 양식 미결정 열: 양식 저장 차단, 열 위치 표시
- 양식 저장 실패: 현재 매핑과 편집값 유지
- 빈 셀은 원본과 작업테이블에서 그대로 보존하고 행을 임의로 제외하지 않음
- 숫자 `0`, 음수와 소수는 빈값으로 처리하지 않음
