## 범위와 완료조건

현재 모든 전표의 기본 입력열이 구매 구성과 같다. 견적·주문·구매의 확정 구성을 변경 불가능한 초기 기준으로 보존하고 기존 설정 저장을 재사용한다. 최초 사용은 전표별 기본을 적용하며 기존에 저장한 설정은 자동으로 덮어쓰지 않는다. 환경설정에서 선택 전표의 표시 항목과 Enter 순서를 초기 구성으로 바꾼 후 설정 저장으로 적용한다. 취소는 활성·저장 설정에 영향을 주지 않는다.

판매의 공지·구매처·날짜·구매 의미는 사용자 확인 대기다. 판매 기본과 저장 설정은 유지하고 판매의 초기 구성 복원은 활성화하지 않는다. 미확정 필드를 다른 값으로 추측 연결하지 않는다.

원본 Excel/매핑 양식, 입력행·저장 전표, 공통 배송 정책, 상단 정보, 다른 전표 설정, 공유 사용자 정의 항목과 열 너비를 초기 구성 변경으로 삭제하지 않는다. DB schema, 외부 앱·원장·서버 계약과 공식 경로는 바꾸지 않는다.

## 확정 초기 구성

| 전표 | 필드 순서 |
|---|---|
| 견적 | 품목코드, 품목명, 규격, 수량, 단가, B단가, A판매, B판매, 적요, 행사가, 적요2 |
| 주문 | 품목코드, 품목명, 규격, 수량, 단가, 공급가액, 메모, 적요(직원), 공지단가 |
| 구매 | 코드, 품명, 규격(기본), 수량, 단가, 공급가, 간단설명(품위), 지시사항, 출고가 (공지), 판매no. |

공급가액은 기존 계산 필드이며 Enter 이동에서 제외한다. 나머지 편집 필드는 위 순서대로 이동한다. 견적 적요는 기존 ERP 보고서의 memo이며 적요2는 memo2다. 표시명과 매핑 후보를 전표별로 정렬하되 기존 필드 identity와 저장값을 유지한다.

## UI와 검증

기존 환경설정 모달과 공통 의미 토큰·버튼을 재사용한다. 새 앱/헤더/테마를 만들지 않는다. 대표 데스크톱·모바일, 일반·다크에서 버튼과 순서·값 보존을 검증한다. 기존 원본/입력표 구분은 유지한다. 검증 대상은 기본 구성, 변경·저장·재로딩, 초기 복원·취소, 다른 전표/사용자 항목/입력값 보존, 견적 가격·적요의 매핑 및 보고서 회귀다.

구현·검증 결과와 GitHub 반영 정보는 작업 종료 시 갱신한다.

## 구현 및 로컬 검증 결과

- 초기 구성과 사용자 저장 구성을 분리하고 전표별 표시명·매핑 별칭을 적용했다. 견적 적요2는 기존 동적 열 생성 경로로 편집·보존한다.
- 환경설정에서 복원 선택을 임시 보관하고 `설정 저장` 시 적용한다. 복원 재렌더링 전 미저장 상단 선택도 보존한다.
- 직접 실행 통과: 신규 초기 구성·매핑 검증, 설정 UX, 독립 복구, 앱헤더, 견적 F8, 구매 판매 출력, FieldDefinition V2, 공식전표 기준/쓰기 경계, 다전표, 입력 양식, 클립보드, 공란 행, 구조화 파서, 6A/6C UI 경계, 미매칭 UI, 공식 수정 경계, repository validation(24 checks).
- UI 변경에 맞춰 cache token 및 기존 UI 기준 해시만 갱신했으며 검증 범위를 제거하지 않았다.
- 실제 Chrome 검증은 PR CI의 별도 job에서 수행한다. 현재 환경에는 로컬 Chrome이 없고 제공된 Cloud Browser는 localhost 접속을 차단했다. 우회하지 않고 같은 테스트를 기존 GitHub CI 환경에서 실행한다.
