## 범위와 완료조건

기존에는 모든 전표의 기본 입력열이 구매 구성과 같았다. 견적·주문·구매·판매의 확정 구성을 변경 불가능한 초기 기준으로 보존하고 기존 설정 저장을 재사용한다. 최초 사용은 전표별 기본을 적용하며 기존에 저장한 설정은 자동으로 덮어쓰지 않는다. 환경설정에서 선택 전표의 표시 항목과 Enter 순서를 초기 구성으로 바꾼 후 설정 저장으로 적용한다. 취소는 활성·저장 설정에 영향을 주지 않는다.

판매의 공지·구매처·날짜·구매는 후속 사용자 지정으로 확정됐다: 공지=금액1(판매), 구매처=적요3(판매), 날짜=사용자지정 문자, 구매=금액2(판매). 판매도 초기 구성·복원에 포함한다. 기존 사용자 설정은 자동 덮어쓰지 않는다.

원본 Excel/매핑 양식, 입력행·저장 전표, 공통 배송 정책, 상단 정보, 다른 전표 설정, 공유 사용자 정의 항목과 열 너비를 초기 구성 변경으로 삭제하지 않는다. DB schema, 외부 앱·원장·서버 계약과 공식 경로는 바꾸지 않는다.

## 확정 초기 구성

| 전표 | 필드 순서 |
|---|---|
| 견적 | 품목코드, 품목명, 규격, 수량, 단가, B단가, A판매, B판매, 적요, 행사가, 적요2 |
| 주문 | 품목코드, 품목명, 규격, 수량, 단가, 공급가액, 메모, 적요(직원), 공지단가 |
| 구매 | 코드, 품명, 규격(기본), 수량, 단가, 공급가, 간단설명(품위), 지시사항, 출고가 (공지), 판매no. |
| 판매 | 품목코드, 품목명, 규격, 수량, 단가, 공급가액, 적요, 출고지시, 공지, 구매처, 날짜, 구매 |

공급가액은 기존 계산 필드이며 Enter 이동에서 제외한다. 나머지 편집 필드는 위 순서대로 이동한다. 견적 적요는 기존 ERP 보고서의 memo이며 적요2는 memo2다. 표시명과 매핑 후보를 전표별로 정렬하되 기존 필드 identity와 저장값을 유지한다.

판매 금액1·금액2·적요3는 기존 ERP catalog에 정확한 행 정의가 없어 SmartInput 소유 보조 입력값으로 구분한다. 상단으로 분류된 기존 공지·구매·구매처 ID를 재해석하지 않는다. 출고지시는 기존 편집 가능한 판매 행 ERP ID를 사용한다. 날짜는 기존 문자형 사용자 슬롯을 재사용하거나 빈 슬롯을 배정하며, 기존 슬롯·값을 덮어쓰지 않는다. 빈 슬롯이 없으면 원래 설정을 유지하고 이유를 표시한다.
