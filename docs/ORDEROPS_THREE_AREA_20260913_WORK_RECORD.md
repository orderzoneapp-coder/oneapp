## 독립 검증 보완

후속 독립 검증에서 확인된 F-01~F-04를 같은 3영역 범위 안에서 보완했다. 다중 API 주문은 회사·문서 ID·Revision·hash와 불변 원본 기준선으로 동일/변경/추가/제외를 구분하며, 동일 자료는 재적용하지 않고 변경 자료는 B/W/N 충돌을 먼저 해결한다. 미변경 행의 담당·창고·구매·대체·이력·출고 초안은 호환 가능한 범위에서 유지하고, 저장 실패는 현재 작업과 준비 자료를 변경하지 않은 채 재시도할 수 있다.

Excel 선택 버튼은 좌측 드롭/파서 안으로 이동했고, ORDER Q·재고·Cloud 완료본·이전 복구 보조 메뉴도 좌측 자료 준비 영역으로 모았다. 중앙 하단 중복 불러오기 메뉴는 제거했다. 우측 전표 목록은 주문일·원본/읽기용 계산금액·적요를 표시하고, 체크한 전표의 원본금액·계산금액·미확인·오류를 단위별 수량과 분리해 합산한다.

격리 브라우저 재인수에는 실제 IndexedDB 저장 실패 후 비파괴 재시도, PUBLISHED 복구본 재선택·재진입, 동일 Revision 멱등, A 변경/B 미변경 작업 보존, 파서 내부 버튼, 중앙 메뉴 부재, 우측 전표 열과 선택 금액을 포함한다. 공식 ORDER Q 원장과 운영 계정에는 테스트 쓰기를 하지 않는다.

## PR #607 독립 재검증 후속 보완

독립 재검증에서 출고분석과 주문 미교체 구매/판매 참고자료 적용이 `workbenchSourceBaselines` 또는 `workbenchPreparedShipmentDrafts`를 새 작업본에 전달하지 않는 R1·R2가 확인됐다. `performAnalysis()`는 엔진의 기존 작업본 재계산 보존 목록과 같은 기준으로 두 필드와 충돌 기록을 복제하고, `applyFiles()`의 주문 미교체 분기는 불변 원본 기준과 다중 출고 초안을 함께 복제한다. 주문 교체·원장 소유권·복구 payload schema는 변경하지 않는다.

브라우저 회귀검사는 `다중 API 적용 → B 담당/창고/구매/출고 초안 수정 → A Revision 2 적용 → 구매만 적용 → 판매만 적용 → 출고분석 → IndexedDB 저장·재진입 → A Revision 3 적용`을 실제 배포 함수와 저장소 경계로 실행한다. 마지막 단계에서 A는 최신 수량을 받고 B의 작업값과 다중 출고 초안은 유지되며, 조정 감사에는 A 변경과 B 불변이 구분되어야 한다.
