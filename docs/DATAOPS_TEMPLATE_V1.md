# DataOps Excel 양식 V1

## 적용 범위

`DATAOPS_DEFAULT_V1`을 항상 기본 양식으로 적용한다. 기존 DataOps의 기초·매입·매출·실사 계산과 저장 데이터는 마이그레이션하거나 일괄 변경하지 않는다. 양식 기능은 Excel 입력을 기존 파서 필드에 연결하는 앞단 계층이다.

## 사용자 흐름

1. 기초·주문·매입·매출·실사 Excel 파일을 작업화면에서 선택한다.
2. 각 파일의 시트와 헤더 행을 자동 분석한다.
3. 코드·품명·규격·단위·수량·단가·거래처·매입처 매칭·일자·기본구분을 자동 연결한다.
4. 관리자는 자동 결과를 확인하고 필요한 필드명, 필수 규칙, 작업 열 순서를 수정한다.
5. 업로드 전체의 분석 결과를 한 번에 반영하여 새 양식으로 저장한다.
6. 다음 작업부터 저장한 양식을 선택하면 역할별 필드명이 자동 적용된다.

양식 목록과 활성 양식은 브라우저 로컬 저장소에만 저장된다. 기본 양식은 수정하거나 삭제하지 않으며, 변경 시 사용자 양식으로 복제한다.

## 필드 정책

| 작업 필드 | 입력 | 비고 |
|---|---:|---|
| 코드 | 가능 | 입력된 코드가 마스터에 없으면 가져오기 차단 |
| 품명·규격·단위 | 가능 | 코드가 없고 품명이 정확히 일치하면 마스터 코드 보강 |
| 기초·전일재고 | 가능 | 기존 `기초` 필드에 연결 |
| 주문·출고예정 | 가능 | 미출고현황 목적에서만 잔량 계산에 사용 |
| 입고·구매 | 가능 | 기존 `입고` 필드에 연결 |
| 출고·판매 | 가능 | 기존 `출고` 필드에 연결 |
| 잔량·실사 | 가능 | 기존 `실사` 필드에 연결 |
| 단가 | 가능 | 기존 단가 수정 기능 유지 |
| 전산잔량 | 불가 | 서버 계산값 |
| 예상잔량 | 불가 | 미출고 양식의 `전산잔량 - 주문` 계산값 |
| 오차·차이·로스 | 불가 | `실사 - 전산잔량` 계산값 |
| 판정·감사·revision·hash | 불가 | 시스템값 |

필수항목은 역할별로 관리자가 지정한다. 지정된 필드가 파일에 없으면 `TEMPLATE_REQUIRED_FIELD_MISSING`으로 분석을 차단하고 누락 필드를 표시한다.

## 목적별 계산

- `STOCK_LEDGER`: 기존 계산을 유지한다. 주문 파일과 주문 열은 재고 계산에 포함하지 않는다.
- `UNSHIPPED_STATUS`: 기존 전산잔량은 변경하지 않고 `예상잔량 = 전산잔량 - 주문·출고예정`을 별도로 계산한다.
- `GENERIC_DATAOPS`: 기본적으로 주문을 계산에 포함하지 않으며 양식 설정값을 따른다.

잔량을 관리자가 직접 수정하면 기존 방식대로 오차·로스를 다시 계산한다. 오차·전산잔량·예상잔량은 화면과 Gateway/ONEAPP 양쪽에서 수정 불가 필드로 유지한다.

## 저장 충돌

양식은 `version`과 `revision`을 가진다. 사용자 양식을 변경 저장할 때 화면의 revision이 최신값과 다르면 `TEMPLATE_VERSION_CONFLICT`로 차단한다. 기본 양식은 덮어쓰지 않고 항상 새 양식으로 저장한다.

## 이번 작업에서 하지 않은 일

- 운영 데이터 변경 또는 운영 URL 호출
- 실제 서비스 자격증명 생성·조회·교체
- Script Properties 변경
- Apps Script push·deploy·redeploy
- 테스트 프로젝트 생성
- Git commit·push·PR 생성
