# ORDER Q 복원본 기본기능 안정화

- 기준: 2d8ad531e5568860806de166912b59364a523833 (PR #621 병합본).
- 목적: 복원한 화면을 유지하면서 재고 수정·단위 합계·수불 누락과 NEXUS 복귀 재시도 오류를 국소 수정.
- 범위: 기본 Excel 입력/주문/창고재고/수불/작업본 저장/Excel 출력. API 확대, 3영역 재설계, 공식 전표·중앙 원장 변경 없음.
- 사용자 “개발 진행해”에 따른 실행 담당 자체 검증이며 외부 독립 승인으로 표시하지 않음.

## 변경

1. F05: 배분 창고 수정값으로 주문별 배분·구매 필요수량 재계산. 원본 inventory/sourceFiles는 변경하지 않고 override 보존. 후보 작업본 재계산 성공 후 교체.
2. F06: 동일 상품도 EA/BOX/단위 미입력을 분리. 규격에서 환산하지 않음. 화면/Excel 단위 표시, 주문·재고 단위 불일치의 자동 배분·잔량 계산 보류.
3. F07: 구매에만 있는 상품도 수불에 표시. 해당 단위 재고가 없으면 재고·잔량은 미확정 공란이며 확정 0으로 바꾸지 않음.
4. F08: 실제 구매/판매 Excel 파서부터 규격·명시 단위·공란 수량·0·음수 보존. 잔량의 기존 재고−주문 의미는 유지.
5. 구매 출력: 화면의 최종 구매 선택과 Excel이 같은 계산을 사용. 음수재고가 있는 경우 주문행 배분 부족과 상품 전체 재고보충은 다른 양이므로 Excel에 최종 상품 구매수량을 한 번만 별도 표시. 예: 주문10/재고−2는 주문배분10, 최종구매12. 단위 불일치·재고 없음은 자동 구매 출력 제외.
6. NEXUS: 실패 후 이전 앱 재연결 중에도 실패 대상·이력 방향 보존. 오래된 READY/timeout 무시, 이력 복원 중 중복 재시도 방지.

## 검증 범위

- 신규 계산 회귀: 엔진/실제 화면 모델/recovery JSON/실제 XLSX 재개방. CI 등록.
- 기존 shipping: 118주문/286재고 reference, 배분·원본 보존·서식·복구.
- 실제 Chromium: Excel 입력→수량·단가 수정→임시저장→reload/복구→주문·수불·재고→Excel 재개방 및 F05~F08 입력/표시/출력.
- NEXUS 실제 클래스 결정적 재현 및 Chromium 지연 READY/이력 재시도와 기존 앱 이동.
- 공유 snapshot, 대체 이력, ORDER Q/출고 owner, Cloud 실패안전, client safety, repository validation, PR/main CI.

## 남은 경계

- 창고 배분 우선순위와 음수재고 정책 전체를 재설계한 것이 아님. 상품별 최종 구매 선택을 옛 배분값으로 덮어써 차이를 숨기지 않음.
- 동적 창고 헤더/자료 종류·시트 별칭(F02/F03)은 별개 후속 항목. 전체 감사 지적이 모두 해결됐다고 보고하지 않음.
- 과거 엔진/워크북 blob 동일성은 롤백 당시의 사실. 이 안정화부터 엔진3.19.1/워크북4.9.1로 변경.
- 운영 자료에 테스트 입력·복구 쓰기 없음. 배포·실제 제공 코드 일치·관리자 업무검수는 구분.
