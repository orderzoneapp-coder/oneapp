## 확인한 원인

SmartInput 화면 자체는 로그인 완료를 비동기로 기다린 뒤 여는 구조가 아니었다. 로그인·회사 식별값은 세션 저장소에서 동기 조회하고 정적 화면을 먼저 표시한다.

견적서 목록이 늦거나 전체 실패로 보이던 직접 원인은 다음과 같다.

1. 견적서, 설정, 거래처 관계, 별칭 매핑, 원본 이미지 등 여섯 저장소를 하나의 `Promise.all` 결과로 묶었다.
2. 견적서와 무관한 보조 저장소 하나만 실패해도 견적서 목록 전체를 실패 상태로 표시했다.
3. IndexedDB 버전 갱신이 다른 탭에 막힐 때 별도 `blocked` 처리가 없어 일반 시간 초과까지 기다렸다.

견적서는 현재 브라우저의 SmartInput IndexedDB에 저장되는 로컬 자료다. 따라서 이번 개선은 로그인 직후 현재 브라우저의 견적서를 즉시 여는 경로이며, 다른 브라우저·기기에서 견적서를 자동 복구하는 서버 동기화 기능은 아니다.

## 적용 내용

### 견적서 목록 로딩

- 견적서 저장소만 읽는 `loadEstimateLibrary()` 빠른 경로를 추가했다.
- 견적서 목록과 설정·참조 데이터의 로딩 상태와 오류를 분리했다.
- 정적 화면 초기화 직후 견적서 로딩을 독립 실행한다.
- 실패 화면에 실제 오류와 다시 불러오기 동작을 제공한다.
- IndexedDB 업그레이드가 다른 화면에 막히면 즉시 원인과 조치 방법을 표시하고, 열린 연결은 버전 변경 시 닫는다.

### 거래처 관계 설정

- 배송 거래처만 지정해도 관계를 저장할 수 있다.
- 세무거래처는 선택사항으로 변경했다.
- 기존 세무 지정도 `세무 지정 안 함`으로 해제할 수 있다.

### 양방향 삭제

- 개별 견적서를 삭제하면 이를 참조하는 모든 연동견적서에서 해당 원본 연결과 품목을 제거하고 재구성한다.
- 연동견적서에서 품목을 삭제하고 저장하면 그 품목에 연결된 모든 원본 행을 삭제한다.
- 반영 결과 원본 견적서의 유효 품목이 0개가 되면 해당 원본 견적서를 자동 삭제한다.
- 자동 삭제된 원본이 다른 연동견적서에도 연결돼 있으면 그 연동견적서도 함께 재구성한다.
- 관련 원본 수정, 원본 삭제, 연동견적서 재구성은 견적서 저장소의 한 트랜잭션으로 처리한다.
- 열려 있던 작업본은 삭제된 원본 연결만 제거하고 가능한 편집 내용은 유지한다.
