# ORDER Q 수기 주문 상품 마스터 검색 명세

- 버전: vNext 0.8.0
- 우선순위: 수기 주문입력 P0
- 원칙: 공통 마스터는 읽기 전용으로 사용하고 주문 거래값과 분리한다.

## 목적

- 빈 상품행에는 매칭 상태를 표시하지 않고, 품목코드 또는 품명을 입력한 뒤에만 매칭완료·매칭실패를 표시한다.

주문 행의 품목코드에서만 공통 상품 마스터를 검색한다. 관리자가 후보를 선택하면 주문 당시의 품목코드·품목명·규격·박스당수량·단위와 실제 `productId`를 저장한다. 수량·단가·합계·부가세·메모는 이번 주문의 거래값으로 별도 입력한다.

## 동작

1. 품목코드에 한 글자 이상 입력하면 최대 8개 후보를 표시하며 품목명에서는 검색하지 않는다.
2. 후보는 가장 관련 높은 상품의 품목코드 앞 6자리 카테고리를 먼저 묶고, 그 카테고리 안에서는 품목코드 오름차순으로 표시한다.
3. 후보는 품목코드, 품목명, 규격, 박스당수량, 단위, 출고가, 제2품명/검색정보와 출처를 표시한다.
4. 마우스 선택 또는 위·아래·Enter로 확정하면 기본정보와 헤더에서 선택한 단가를 자동입력하고 수량 칸으로 이동한다. 기본 판매가는 유효한 행사가를 우선하고 행사가가 없거나 0이면 출고가를 적용한다. 출고가 공란은 0으로 보정하지 않는다.
5. 선택 뒤 품목코드나 품목명을 바꾸면 마스터 연결을 해제한다.
6. 후보가 없어도 직접입력을 허용하고 `MATCH_FAILED`로 저장한다.
7. 실제 마스터 후보를 선택한 행만 `MATCHED`로 저장한다. 단순히 코드와 품명을 입력한 행은 매칭완료로 간주하지 않는다.

## 수기입력 흐름과 메모 구분

- 신규 화면 입장 시 거래처명에 포커스를 둔다. 거래처명에서 Enter를 누르면 출하창고로 이동한다.
- 출하창고와 거래유형은 `oneapp.orderq.manual-defaults.v1`에 마지막 선택값을 저장하고 다음 신규 주문에서 복구한다.
- 일자는 `YYYY-MM-DD` 형식을 유지하며 포커스 시 일(day) 두 자리를 선택한다.
- 일자를 클릭하거나 달력에서 선택하면 일(day) 두 자리에 포커스하고, 위·아래 화살표로 하루씩 증감한다.
- `orderMessage`는 전표 메모이며 주문건 전체 전달사항이다.
- `ORDER_ITEM.memo`는 상품별 메모(적요)이며 해당 상품 행에만 적용한다.
- 시스템 주문정보는 주문 ID·Revision·상태를 표시하는 읽기 전용 정보다.
- 기본 Enter 동선은 거래처 → 출하창고 → 품목코드 → 수량 → 단가 → 적요다. 출하창고·거래유형이 이미 지정됐으면 거래처에서 품목코드로 바로 이동한다.
- 마지막 행의 적요에서 Enter를 누르면 빈 행 하나를 자동 생성한다. 초기 빈 행도 하나만 제공한다.
- 품목명·규격·박스당수량·단위는 마스터 선택값을 불러오지만 사용자가 직접 터치해 수정할 수 있다.
- 합계는 수량×단가 제안값이며 사용자가 할인·잔액정리를 반영해 직접 수정할 수 있다.
- 단가 헤더는 기본 `판매가`인 드롭다운이다. 헤더 선택이나 단가 셀의 ▲▼·키보드 위·아래 화살표는 1원 증감하지 않고 `판매가 → 출고가 → 도매A → 도매B → 상장가 → 시중가 → 행사가` 중 공통 마스터에 값이 있는 항목을 순환한다. 선택하면 헤더명과 마스터 매칭 행 전체의 단가가 함께 바뀐다. 직접 수정한 행은 `직접입력`, 여러 기준이 섞인 주문은 `혼합단가`로 헤더에 표시한다.
- 열 추가 메뉴는 박스당수량·단위·부가세 표시를 제어한다. 부가세는 합계의 10% 제안값이며 직접 수정할 수 있다.
- 입력 행은 입력순·코드순·품명 가나다순·단위순으로 정렬할 수 있다.
- 표 헤더 끝선을 드래그해 열 너비를 조정하며, 변경 후 노출되는 `열너비 저장` 버튼을 눌러야 다음 접속에도 유지된다.

## 데이터 원본과 저장

- 검색 우선순위: 같은 출처의 `MerchOpsDB/master_products` 공통 마스터 → ORDER Q 이력 상품.
- 공통 마스터와 ORDER Q 이력의 품목코드가 같으면 공통 마스터를 우선한다.
- 주문 품목에는 `productId`, 입력 원문, 주문 당시 품목코드·품목명·규격·`boxQuantity`·`finalUnit`, 수량·단가·단가 종류 `priceType`·수정가능 `supplyAmount`·선택 `vatAmount`·메모, `matchStatus`, `matchSource`를 저장한다.
- 기존 `rawUnit`은 SmartParser 원문 증거와 호환 인덱스를 위해 유지하며 박스당수량으로 재사용하지 않는다.
- 공통 마스터 원본은 ORDER Q가 수정하거나 복제 저장하지 않는다.

## 이번 안정화에 포함한 P0

- 주문·판매 양쪽 상품코드가 서로 다르면 품명이 같아도 출고 연결을 금지한다.
- SmartParser의 부분 변경·취소 메시지는 주문 전체를 자동 교체·취소하지 않고 수기 검수 대기로 저장한다.
- 음수 판매(반품·취소 역분개)는 파서사전 학습 근거에서 제외한다.
