## 배포 승인 후 후속 검증

- 사용자 지시: **“배포 해서 운영확인하라”**. 기존 작업 브랜치에서 수정·검증 후 PR·병합·GitHub Pages 배포 및 운영 기술 확인까지 진행한다.
- 최신 원격 `main`의 `d5d571a1f90081682572449aa4dea396a2703334`를 병합해 다른 앱의 운영 복구 변경을 보존했다. SmartInput 생산 소스 충돌은 없었다.
- GitHub Pages API로 `legacy`, `main`, `/`, `https://oneapp.orderz.co.kr/` 배포 경계를 확인했다. 서버 코드·배포 ID·공식 전표 V2 활성화 조건은 이번 배포에서 변경하지 않는다.
- 기존 별칭 결과 보존은 owner의 읽기 전용 Snapshot과 SmartInput 기존 settings 캐시로 보완한다. 초기 진입은 캐시만 읽고, 최초 준비는 기존 전체 기준정보 새로고침으로 실행한다. 회사 없는 기존 자료를 임의의 다른 회사로 귀속하지 않는다. 기존 입력행은 자동 재분석하지 않는다.
- 견적 준비 조회 이전에 busy가 설정되지 않던 구간을 수정했다. 실제 전체 브라우저 E2E에서 두 번째 견적 저장까지 통과했으며 준비 실패·취소·중복 클릭·호스트 이동 대기를 별도 검증했다. 상세: `estimate-save-resolution.md`.
- 운영 확인은 새 임시 브라우저 프로필의 합성 자료와 실제 배포 자산을 사용한다. 개인 프로필과 운영 원장에 테스트 거래를 만들지 않는다. 배포 asset 비교와 실제 NEXUS 호스트 검사를 별도 증거로 남긴다.
