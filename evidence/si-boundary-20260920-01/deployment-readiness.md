# SmartInput 배포 승인 후 검증

작업 `SI-BOUNDARY-20260920-01`, 기준 명세 v1.5. 사용자의 “배포 해서 운영확인하라” 지시에 따라 PR·CI·병합·Pages 배포·실제 운영 자산 확인을 진행한다. 이 기록은 소스 검증과 배포 증거를 구분한다.

## 구현 판정

- 구조: SmartInput JS 63→51개, 본체 정적 모듈 경로 54→41개. 별칭 결과 보존을 위해 owner readonly 발행 모듈 1개를 별도 추가했다. 기존 함수를 실제 통합하고 폐기 파일을 제거했다.
- 정확성: 별칭 원문 `노란거 2개`의 최종 코드 `001`, 품명 `수입바나나`, 규격 `13kg`, 수량 `2`, 단위 `개`가 보존된다. 회사·사용자·hash 검증, 첫 미준비, 실패 시 이전 기준 유지, 같은 원문 명시 재분석 및 활성 작업본 보존을 확인했다.
- 견적: 준비 조회부터 busy를 유지해 중복 저장·조기 화면 이동을 막았다. 첫 저장→단가 1,750 수정 저장→초기화→두 행의 두 번째 견적 저장을 포함한 전체 브라우저 E2E가 통과했다. 실패·취소·이동 대기·수량 0 회귀도 통과했다.
- 독립성: 최종 경계 브라우저 17개 검사 통과. 직접/호스트 진입, 일반 입력, 자동저장, Excel 출력, 4개 탭, 공통 UI 장애 시 복구와 준비된 별칭의 재분석/재진입에서 원장 읽기·owner 쓰기·외부 요청이 0이었다. 명시적 조회·기준정보 갱신은 실제 owner 읽기의 양성 대조로 확인했다.
- 기존 6-domain generation은 그대로 원자적으로 활성화한다. 별칭 snapshot은 기존 settings의 별도 결과이며 부분 성공을 표시한다. owner 저장소 버전·스키마·업무 엔진·공식 서버 활성화 조건은 변경하지 않았다.

## 성능 근거

동일 Windows PC/Chrome, 상품 600개·입력 20행의 합성 자료, Warm 20회 nearest-rank p95이다. 실제 사용자 자료의 모든 크기나 서버 시간을 대표하지 않는다.

| 항목 | 변경 전 | 배포 후보 | 기준/판정 |
|---|---:|---:|---|
| 로컬 초안 표시 | 4,283.8ms | 345.1ms | 500ms 이하 PASS |
| 직접 진입 사용 가능 | 4,453.3ms | 504.3ms | 실제 호스트 이동과 구분 |
| 20행 분석 | 1,592.5ms | 137.3ms | 결과 보존 별도 검증 |
| 분석 중 owner 저장소 읽기 | 80회 | 0회 | 반복 조회 제거 |

최종 성능과 경계 브라우저의 본체 SHA256은 `14c8e4166b064b6fe26c165e6f5523219b41ce85f3aeb5e08706651e839ecf6b`로 일치한다. `deploy-final-performance.json`, `after-boundary-browser.json` 참조. 실제 NEXUS host 이동·클릭은 `local-host-navigation.json`과 별도 운영 계측을 사용한다. 공통 계층만의 Warm 차단 150ms는 전체 이동 시간으로 대체하지 않고 미측정으로 남긴다. 기존 기준을 낮추지 않는다.

20/600/3000행의 견적·구매판매 출력 순수 계산 6개 결과 hash는 기존 증거에서 모두 기준선과 같았다. 이후 계산 본문은 변경하지 않았으며 이번 측정에서 다시 실행한 것으로 표시하지 않는다. 실제 XLSX 직렬화는 최종 경계 브라우저에서 확인했다.

전체 E2E의 본체 hash는 `1d28dea979abf9e79c869e12149434f4256e5facc15008cb0e082a3f20d71147`이다. 그 뒤 변경한 분석 revision/안내 처리는 최종 Node 및 17개 경계 브라우저에서 검증했다. 견적 저장 함수는 그 이후 바뀌지 않았다. 전체 E2E 결과를 다른 hash의 전체 재실행으로 표현하지 않는다.

## 운영 확인 경계와 사용 안내

GitHub Pages는 main 루트의 저장소 단위 배포다. 실제 Pages build SHA, 배포된 변경 자산의 Git blob hash, 운영 URL에서의 직접 진입·실제 NEXUS host·입력·로컬 자동저장·복구를 따로 확인한다. 임시 브라우저 프로필과 합성 자료를 사용하고 외부 업무 요청을 차단한다. 운영 원장에 테스트 거래를 만들지 않는다.

처음 적용한 프로필에서 이전 별칭·이력을 사용하려면 **기준정보 → 전체 기준정보 새로고침**을 한 번 실행한다. 준비 전에 분석한 행은 그대로 유지되며, 같은 원문의 **분석**을 누르면 새 기준이 적용된다. 직접 수정한 값은 기존 편집 보존 규칙을 따른다. 캐시는 공식 원본이 아니다.

실제 로그인 서버·다기기 동기화·실거래 확정·사용자 자료 업무검수는 이 프런트엔드 운영 기술 확인에 포함하지 않는다. 배포 승인으로 미활성 서버 기능을 새로 활성화하지 않는다. 원래 버전으로 복구할 때는 이 작업 PR만 revert하고 원장·초안·견적 DB를 삭제하거나 버전을 내리지 않는다.
