## 성능·남은 검증

별칭 기준 판단 전 현재 소스의 `after-final-performance.json`을 변경 전 `baseline-performance.json`과 비교한다. 최종 경계 브라우저 검사와 성능 자료의 main SHA256은 `db7f1dbc044e1c23051505cefcc07444b1dee049927f5a8218930cc429d5641f`로 같다. 순수 행렬 계산과 브라우저 작업의 결과는 구분하며, 생성된 Excel 전체 작업 또는 실제 NEXUS 앱 이동 성능까지 확대하지 않는다. 실제 사용 데이터·인증 서버·운영 배포는 검증 범위에 포함하지 않았다.

| 같은 fixture, 각 20회 p95 | 변경 전 | 현재 중간 구현 | 판정 |
|---|---:|---:|---|
| 20행 분석, 상품 600개 | 1,592.5ms | 183.8ms | 88.5% 감소 관측, 정확성 별도 판정 |
| Warm 로컬 초안 표시 | 4,283.8ms | 458.1ms | **500ms 기준 통과** |
| Warm 직접 진입 사용 가능 | 4,453.3ms | 638.3ms | 85.7% 감소 관측, 실제 호스트 이동 KPI의 대체 아님 |
| 분석 중 owner 저장소 반복 읽기 | 80회 | 0회 | 제거 확인 |

초기 JS 요청은 62→48개다. 최종 Warm 20회 모두 전체 정적 자산 57개와 JS 48개가 `transferSize=0`임을 확인했다. 행마다 재생성하던 매핑 정의를 렌더 단위로 재사용하고, 같은 열의 불필요한 이동과 중복 레이아웃 처리를 줄였다. 이미 필수인 본체만 modulepreload하며 선택 기능은 미리 읽지 않는다. 견적·구매판매 출력 20/600/3000행의 6개 결과 hash는 모두 같다. 이 순수 계산은 이전 중간 측정 증거를 참조하며 이번 최종 브라우저 계측에서 재실행하지 않았다. 계산 본문은 변경하지 않았으므로 순수 계산 시간 차이를 본 리팩터링 효과로 단정하지 않는다. 상세는 `performance-comparison.json`이다.

실제 NEXUS 앱 이동 p95 1초, 공통 계층 차단 p95 150ms, 클릭 피드백 p95 100ms는 별도 계측이 남았다. 직접 진입 수치나 본체 실행 시간으로 대체하지 않는다.

기존 전체 브라우저 E2E는 입력·검색·후보 선택/취소·주문 조회·구매/판매 공식 저장·첫 견적 저장까지 진행했지만, 두 번째 견적 저장 대화상자에서 중단됐다. 관련 함수가 기준선과 같다는 사실만으로 기존 오류라고 단정하지 않는다. 추가 상태 수집 실행은 앞선 명시 기준정보 갱신 timeout으로 중단돼 두 번째 저장의 원인은 아직 확인하지 못했다. 증거는 `full-browser-focused-path.json`, `full-browser-estimate-runtime-diagnostic.json`이다. 최신 경계 검사는 통과했지만 넓은 전체 E2E는 미완료로 유지한다.
